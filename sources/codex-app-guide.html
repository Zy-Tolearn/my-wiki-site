Codex App 保姆级全攻略

作者：技术爬爬虾 平台：Bilibili 视频：BV1Kk9kBAEJv 上传日期：2026-04-28

Codex App 最容易被低估的地方，是它看起来像一个“会写代码的聊天窗口”，但真正的定位更接近一个 AI 工作台：它能管理项目、并行跑任务、修改文件、启动服务、打开浏览器验证结果，还能通过插件、自动化、Skills 和 MCP 连接外部世界。

这篇教程的价值，不在于逐个按钮介绍，而在于把 Codex App 的能力串成了一套可复用工作流：小任务直接交给 Agent，复杂任务先计划，重复任务做自动化，稳定流程沉淀成 Skill，外部系统通过 MCP 接入。

一、先把 Codex 当成项目工作台

Codex App 的基础界面是三栏布局：左侧是项目和任务列表，中间是对话，右侧是文件、浏览器、终端等辅助区域。这个结构决定了它不是单次问答工具，而是围绕“项目”组织工作的 Agent 环境。

一个项目可以同时开多个对话，多个项目也可以并行执行。任务列表会显示正在运行、等待批准、已完成等状态。对习惯同时推进多个小项目的人来说，这个任务视图很关键：它让 AI 工作从“我发了一条消息，然后等结果”变成“我在调度一组后台任务”。

二、沙箱是效率和安全的共同前提

Codex App 的权限系统建立在 沙箱权限控制 上：项目文件夹是默认工作边界。Codex 可以直接读写沙箱内文件，但默认不能修改沙箱外文件，也不能随意联网。

这带来一个重要变化：在项目内，它不用每改一个文件都问你，体验接近“放手让它干”；一旦涉及联网、下载依赖、访问外部路径，它会发起提权请求。教程里更推荐自动审查模式：低风险操作自动放行，高风险操作再交给用户确认。

这种设计比单纯写一句“不要乱删文件”可靠得多。提示词是软约束，沙箱是执行边界。

三、复杂任务先进入计划模式

教程里反复出现的一个经验是：复杂任务不要直接开干，先用 计划模式。

计划模式会让 Codex 先澄清关键选择，例如：

  • 要迁移到哪种项目形态？
  • 是否使用 TypeScript？
  • 样式是原样迁移还是重构？
  • 是否需要同时构建并启动本地服务验证？

等用户确认后，Codex 再实施计划。这一步看似慢，其实是在避免最贵的返工：AI 很勤快，一旦方向错了，它会非常努力地把错误做完整。

执行中如果发现方向不对，还可以用“引导”功能中途纠偏。计划模式解决开工前的对齐，引导解决执行中的偏航。

四、真正有用的是完整代码闭环

Codex App 不是传统 IDE，它不强调让你手动编辑代码，而是强调让 Agent 完成闭环：

教程里的网页迁移案例很典型：Codex 完成 Next.js 迁移后，启动本地开发服务器，在内置浏览器里展示页面；用户发现星星图标不对，可以直接在页面上批注，让 Codex 继续修。

这比“AI 给我一段代码，我自己复制到项目里试”前进了一大步。真正的 AI 编程不是生成代码，而是把验证和反馈也纳入同一条工作流。

五、记忆要分项目级和全局级

教程里提到两类记忆：

  • 项目级 AGENTS.md：放在项目根目录，记录项目背景、技术栈、文件约定、用户偏好。
  • 全局自定义指令：对所有项目生效，适合写通用安全习惯和沟通偏好。

项目级记忆让新对话快速理解当前工程；全局记忆则像个人操作守则。比如教程中提到的“禁止脚本批量删除文件”就适合放在全局规则里，因为它不是某个项目的特例，而是所有 Agent 操作都该遵守的安全底线。

六、能力扩展有四条路

模块重点
插件连接 GitHub、Gmail、Netlify、浏览器等服务
自动化把周期性任务变成定时执行的 Agent job
Agent Skills把专业流程封装成可复用说明书
MCP用标准协议接入 Supabase 等外部系统

这四条路对应四种不同需求。

插件适合连接现成服务；自动化适合重复执行；Skills 适合沉淀方法；MCP 适合让 Agent 操作外部系统。它们合在一起，让 Codex 从“项目里的代码助手”变成“能跨工具完成任务的 Agent”。

七、这和 Vibe Coding 的关系

Vibe Coding 常被理解为“用自然语言让 AI 写代码”。这篇教程展示的是更成熟的版本：自然语言只是入口，真正重要的是工作流。

成熟的 Vibe Coding 至少包含五件事：

  1. 用 Git 给 AI 修改提供回滚保险。
  2. 用沙箱控制 Agent 的行动边界。
  3. 用计划模式对齐复杂任务。
  4. 用浏览器和测试验证结果。
  5. 用 Skills、自动化和 MCP 沉淀可复用能力。

这也是 Codex App 工作流 值得单独成页的原因：它不只是一个工具教程，而是一套新的项目执行方式。

八、推荐实践清单

  1. 新项目先让 Codex 初始化 Git 和 .gitignore。
  2. 复杂迁移使用计划模式，不直接开工。
  3. 每个项目维护 AGENTS.md，让新对话继承项目知识。
  4. 高风险操作用沙箱和提权审批兜底。
  5. 重复性跨工具任务做成自动化。
  6. 稳定工作流做成 Skill。
  7. 外部服务优先通过 MCP 或插件接入，而不是临时复制粘贴文档。
  8. 一个任务结束后，下一件事尽量新开对话，减少旧上下文干扰。

结论

Codex App 的核心不是“更会写代码”，而是把 AI 编程从单轮生成推进到项目级执行：它能计划、能修改、能验证、能调用外部工具，也能把经验沉淀成记忆和 Skills。

真正值得学习的不是每个按钮在哪里，而是这套使用姿势：把 Agent 放进受控环境里，让它尽可能自主地完成闭环；人类负责定方向、审风险、做判断。
