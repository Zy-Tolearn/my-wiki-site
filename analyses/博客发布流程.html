博客发布流程

基于 Quartz 将 wiki 中的部分文章发布为静态博客，私有仓库存源码，公开仓库只暴露构建后的 HTML。

架构

LLM-Wiki（私有仓库）
├── wiki/              ← 内容源
├── blog/              ← Quartz 引擎
│   ├── content/       ← Junction 链接到 wiki/
│   ├── quartz.config.ts
│   └── public/        ← 构建产物（gitignore）
└── .github/workflows/deploy-wiki.yml

my-wiki-site（公开仓库）
└── gh-pages 分支      ← 只有 HTML/CSS/JS

搭建步骤

1. 克隆 Quartz 到 blog/

2. 创建 content → wiki 的链接

Windows 用 Junction，Linux/CI 用 ln -s。

3. 安装依赖

确保 blog/package-lock.json 被 git 提交（CI 的 npm ci 需要它）。

4. 配置 quartz.config.ts

关键改动：

  • pageTitle: “LLM-Wiki”
  • locale: “zh-CN”
  • baseUrl: “zy-tolearn.github.io/my-wiki-site”
  • analytics: null
  • ignorePatterns: 加上 “.gitkeep”
  • filters: 把 Plugin.RemoveDrafts() 改为 Plugin.ExplicitPublish()

5. 创建 wiki/index.md

Quartz 需要 content 根目录有 index.md 作为首页。

6. 配置 .gitignore

blog/node_modules/
blog/public/
blog/.quartz-cache/

7. 创建公开仓库

GitHub 上创建 my-wiki-site 公开仓库。

8. 创建 Personal Access Token

GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)

  • 勾选 repo 和 workflow 权限
  • 复制 token

9. 添加 Secret

LLM-Wiki 仓库 → Settings → Secrets and variables → Actions

  • Name: DEPLOY_TOKEN
  • Value: 上一步的 token

10. 创建 GitHub Actions Workflow

文件：.github/workflows/deploy-wiki.yml

触发条件：push 到 main 分支且 wiki/ 或 Quartz 配置有变更。

流程：checkout → setup node → symlink wiki → npm ci → quartz build → 推送 public/ 到公开仓库的 gh-pages 分支。

11. 公开仓库开启 Pages

my-wiki-site → Settings → Pages → Source: Deploy from a branch → Branch: gh-pages / / (root)

首次 workflow 运行成功后 gh-pages 分支才会出现。

预览

部署

正常 commit 并 push 到私有仓库即可，GitHub Actions 自动构建并推送到公开仓库。

也可以手动触发：私有仓库 → Actions → Deploy Wiki to GitHub Pages → Run workflow。

踩过的坑

  1. blog/ 里残留 .git 目录会被外层仓库当成 submodule，导致文件不被追踪。删掉后需要 git rm --cached blog 再 git add blog/
  2. GitHub Actions 的 DEPLOY_TOKEN secret 需要 repo + workflow 权限
  3. gh-pages 分支在首次 workflow 成功后才会自动创建，之后再去 Pages 设置里选
  4. Windows 下用 Junction 链接 content → wiki，CI 环境（Linux）用 ln -s

常见问题

npm ci 报错找不到 package-lock.json

如果用 pnpm 初始化的项目，CI 里也要用 pnpm。workflow 中需要：

  • 添加 pnpm/action-setup@v4 步骤
  • 把 npm ci 改为 pnpm install --frozen-lockfile
  • 把 npx quartz build 改为 pnpm quartz build
  • 确保 blog/pnpm-lock.yaml 已提交到 git

esbuild 版本冲突（Host version does not match binary version）

node_modules 里缓存了旧的 esbuild 二进制文件。解决：

quartz build 报 Permission denied

CI 的 Linux 环境下 quartz/bootstrap-cli.mjs 没有执行权限。在 workflow 的 build 步骤前加：

deploy 报 not found deploy key or tokens

检查：

  1. Secret 名字是否为 DEPLOY_TOKEN（全大写，下划线）
  2. Token 是否勾选了 repo + workflow 权限
  3. Token 是否过期

git rm —cached blog 报 pathspec did not match

确保在仓库根目录（D:\LLM-Wiki）执行，不是在 blog/ 子目录里。
