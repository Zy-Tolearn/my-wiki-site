Git 实战指南

从 SSH 配置到日常同步、冲突解决，记录 Git 使用中的完整流程和每条命令的含义。

核心概念：公钥与私钥

SSH 密钥对是一组数学关联的密钥，用于身份验证：

  • 私钥（id_ed25519）：存在本地 ~/.ssh/ 目录，绝不外泄。相当于钥匙。
  • 公钥（id_ed25519.pub）：上传到 GitHub，任何人可见。相当于锁。

原理：只有你的私钥能匹配你的公钥。GitHub 用你上传的公钥验证身份，私钥永远不离开本地。

配置步骤

1. 检查已有密钥

如果已有 id_ed25519 和 id_ed25519.pub，可跳到第 3 步。

2. 生成密钥对

一路回车（默认路径、空密码）。生成两个文件：

  • ~/.ssh/id_ed25519 → 私钥
  • ~/.ssh/id_ed25519.pub → 公钥

3. 复制公钥

复制输出的完整内容（以 ssh-ed25519 开头的一整行）。

4. 添加到 GitHub

  1. 打开 GitHub SSH 设置
  2. 点击 New SSH key
  3. Key type 选 Authentication Key（用于身份验证；Signing Key 是给 commit 签名用的，按需配置）
  4. Title 随意填写（如”我的电脑”）
  5. 粘贴公钥，保存

5. 测试连接

首次连接会提示确认服务器指纹，输入 yes。看到 Hi 用户名! You've successfully authenticated 即成功。

日常操作：提交与推送

配置好 SSH 后，日常工作就是”改文件 → 提交 → 推送”。

git status — 查看当前状态

显示哪些文件被修改、哪些是新文件、哪些已暂存。是最常用的命令，随时可以跑。

git add — 暂存文件

把指定文件放入”暂存区”（staging area）。只有暂存过的文件才会被下一次 commit 包含。

  • git add . 会暂存所有改动，但容易误提交不相关的文件，建议指定文件名。
  • 文件名含中文或空格时用引号包裹。

git commit — 提交

将暂存区的内容打包成一个”快照”，附上说明信息。-m 后面是提交信息，简要描述这次改了什么。

提交只影响本地仓库，远程还看不到。

git push — 推送到远程

  • origin：远程仓库的别名（克隆时自动设置，指向 GitHub 上的仓库）
  • main：要推送的分支名

把本地的 commit 同步到 GitHub。推送后别人就能看到你的改动了。

git config — 配置身份

Git 要求每次 commit 都带上作者信息。这条命令设置当前仓库的身份。加 --global 则对所有仓库生效。

如果没配置就 commit，会报 Author identity unknown 错误。

同步操作：拉取远程更新

当远程仓库有别人（或其他设备）推送的新内容，而你本地也有改动时，需要先同步。

场景：本地有未提交的改动，pull 被拒绝

error: Your local changes to the following files would be overwritten by merge:
    log.md
Please commit your changes or stash them before you merge.

Git 拒绝 pull，因为远程和本地都改了同一个文件，直接合并会覆盖你的本地改动。

解决方案：stash → pull → stash pop

第 1 步：git stash — 暂存本地改动

把所有未提交的改动（包括已暂存和未暂存的）临时存到一个”藏匿栈”里，工作区恢复到上次 commit 的干净状态。

可以理解为”先把手头的活放一边”。

第 2 步：git pull — 拉取远程更新

  • pull = fetch（下载远程内容）+ merge（合并到本地分支）
  • --tags：同时拉取标签
  • origin main：从远程的 main 分支拉取

现在工作区是干净的，pull 可以顺利执行。

第 3 步：git stash pop — 恢复本地改动

把之前藏起来的改动重新应用到当前工作区，并从藏匿栈中移除。

如果你的改动和刚拉取的远程更新没有冲突，到这里就结束了。如果有冲突，Git 会标记出来。

冲突解决

什么是冲突

当远程和本地修改了同一个文件的同一个位置，Git 无法自动决定保留哪个版本，就会产生冲突。

冲突标记

Git 会在文件中插入冲突标记：

<<<<<<< Updated upstream
（远程的内容）
=======
（你本地的内容）
>>>>>>> Stashed changes
  • <<<<<<< Updated upstream 到 ======= 之间：远程拉取下来的内容
  • ======= 到 >>>>>>> Stashed changes 之间：你本地 stash 恢复的内容

解决步骤

  1. 打开冲突文件，找到 <<<<<<< 标记
  2. 决定保留哪些内容（通常两边都要保留，按时间排序合并）
  3. 删除所有冲突标记（<<<<<<<、=======、>>>>>>>）
  4. 保存文件

解决后的操作

注意：stash pop 遇到冲突时不会自动删除 stash 条目（和无冲突时不同），需要手动 git stash drop 清理。

完整工作流速查

日常提交：
  git add <文件>  →  git commit -m "说明"  →  git push origin main

有远程更新需要同步：
  git stash  →  git pull origin main  →  git stash pop  →  解决冲突（如有）  →  git add/commit/push

踩坑记录

  • 首次 ssh -T git@github.com 会弹出 The authenticity of host 'github.com' can't be established 提示，这是正常的，输入 yes 即可。GitHub 的地址会被记录到 ~/.ssh/known_hosts，后续不再提示。
  • Key type 要选 Authentication Key，不是 Signing Key。
  • git push 显示 Everything up-to-date 不一定是失败，用 git log --oneline -3 确认 HEAD 和 origin/main 是否指向同一个 commit，如果是就说明已经推送成功了。
  • stash pop 有冲突时 stash 不会被自动删除，解决冲突后记得 git stash drop。
