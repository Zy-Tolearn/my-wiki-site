先别急着判断是会话丢失。很多时候，真实的会话文件还在本地，只是左侧列表没有把它们显示出来。

这类问题的关键不是“文件还在不在”，而是三层状态是否对齐：

如果你从 OpenAI 账号直登切到第三方兼容 API，或者换过工作区路径，Codex 可能仍然保存着旧对话，但当前列表读不到。

一、先理解 Codex 的会话列表

Codex 左侧会话列表不是简单地扫描 .codex/sessions/ 文件夹。

它更像是先读取一个本地状态索引：

其中的 threads 表记录了线程、标题、provider、工作区路径等信息。然后 Codex 再根据当前客户端状态做过滤，比如：

  • 当前使用的 model_provider
  • 当前工作区 cwd
  • 当前 workspace roots
  • 是否选中了远程主机

所以，“对话记录不可见”不一定代表 .jsonl 会话文件丢了，也可能只是 threads 表和当前配置不一致。

三、同步前先做安全检查

不要直接改数据库。先做三件事：

  1. 完全退出 Codex，包括 VS Code 等 IDE 中可能启动的 Codex 插件。
  2. 备份整个 .codex 目录，至少备份 state_5.sqlite、.codex-global-state.json 和 sessions/。
  3. 明确当前要同步到哪个 provider 和哪个工作区路径。

真正要同步的不是某一个文件，而是几处状态：

目标是让旧会话同时满足当前 provider 和当前工作区过滤条件。

如果只改 threads 表，不改 sessions/*.jsonl 或 archived_sessions/*.jsonl，后续 Codex 读取事件流时仍可能出现不一致。

七、什么时候不要这么做

下面几种情况不建议直接改：

  • 你没有备份 .codex 目录；
  • 不确定当前 provider 名称；
  • 不确定旧会话对应哪个工作区；
  • state_5.sqlite 打不开或结构已经和原文不一致；
  • 你只是想“清理列表”，不是恢复旧会话。

这不是普通配置修改，而是本地状态库修复。收益是找回旧对话，代价是你要承担状态不一致的风险。

八、这个问题真正值得记住的点

很多桌面工具都会维护多份状态：文件是一份，数据库索引是一份，当前视图过滤条件又是一份。
